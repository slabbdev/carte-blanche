Act 0 · The problem

An agent with a wallet answers to nobody

Agentic commerce is being built fast — OpenAI & Stripe's ACP, Google's AP2, Coinbase's x402, official agent toolkits. Here is what none of them ship:

🤖💳

The agent CAN pay

Today's toolkits expose capture-an-order as a plain function call. If the model decides to spend, money moves. The official PayPal agent toolkit even sets its idempotence key at client level — a framework retry can double-charge (their issue #98).

🧾🚫

No mandate, no receipt

There is no way to say “$60 max this week, groceries only” in a form an agent can be held to. And when the agent buys, no proof of what authorized it survives the transaction.

⚖️❓

Disputes? Nobody's answer

When a chargeback hits an agent-initiated purchase, there is no evidence standard. x402 skips disputes by design; ACP doesn't define them; AP2 is a spec, not a product.

“Audit trail: Nobody provides one.” — Hacker News, on machine payments
the exact gap Carte Blanche occupies
Act 1 · The mandate

Act 2 · The agent shops

Every attempt gets an answer. Both kinds are signed.

Try the purchases the demo agent tried. Allowed ones come back with a receipt; refused ones come back with a signed proof of refusal naming the exact limit that blocked them. (They run in the recorded order — the cumulative cap needs purchases ① and ② to have happened.)

Act 4 · Run the real thing

Thirty seconds, zero credentials

The scripted scenario — mandate, purchases, refusals, verification — with a dev simulator (ids clearly prefixed MOCK-):

git clone https://github.com/slabbdev/carte-blanche && cd carte-blanche
npm install && npm run build && npm run demo

What it prints (from an actual run):

mandate granted: $60 total / $30 per transaction / 7 days (cbmd-…)
purchase 1 OK   -> rcpt-9605aca151997623 (MOCK-0001)
purchase 2 OK   -> rcpt-b29d9b2d0c2fd9b5 (MOCK-0002)
purchase 3 REFUSED -> deny-6096fbb13112cb08 [OVER_TOTAL_CAP]

retry-safety: re-submitting purchase 1 returns the same receipt id (no second PayPal call)

Point it at the real PayPal sandbox (Orders v2 REST) with your developer credentials:

PAYPAL_MODE=sandbox PAYPAL_CLIENT_ID=… PAYPAL_CLIENT_SECRET=… npm start

Or let an actual LLM loose on it — its only payment tools are mandate_status, purchase, my_receipts:

npm start &            # console on :8790
OPENAI_API_KEY=… npm run demo:llm -- <mandate_id> "Buy a keyboard for under $60"
